An early concept with a small prototype, built in public

Security alerts in.
Reviewable fixes out.

Scanners flag vulnerabilities faster than small teams can fix them. PatchPilot aims to read a finding, ask Claude for a minimal fix, check it against the project's own tests, and hand developers a pull request to review.

See the planned flow What exists today

Alerts pile up. Fixes don't.

Static analysis and dependency checkers produce long lists of warnings. Fixing each one means researching the weakness, reading unfamiliar code and writing a safe change, which small engineering teams rarely have time for. The findings sit in a backlog.

Who it is for

Developers and small engineering teams, including open-source maintainers, who want an actionable pull request instead of another report. A person always reviews and merges.

The planned flow, as a replay

This is an illustration that runs in your browser. It is not connected to a backend and does not scan or fix any code.

    
          
    
        
    
      
    
    
    
  
    

    


    
  
    
    
    The prototype you can run
    
    
    A small Python command-line tool reads a SARIF finding, builds a prompt from the flagged file, and asks Claude for a suggested diff. It checks that the diff matches the file before showing it. It does not run your tests.
    
    
    
      
    
        Windows (Command Prompt)
        
      
    
      
    git clone https://github.com/SantasHelperOwo/patchpilot
cd patchpilot
py -m pip install -r requirements.txt
py src\patchpilot.py --sarif examples\sample.sarif --root examples --dry-run
    
    
    
    
    The dry run prints the prompt and needs no API key. Set ANTHROPIC_API_KEY and remove --dry-run to ask Claude. The live call has not been tested yet. Source on GitHub.

    How we plan to use Claude
    
    
    Claude sits at the patch-writing step. The pipeline parses a SARIF finding, collects the vulnerable code and its surrounding context, and sends both to Claude through the Anthropic API with a prompt that asks for a minimal unified diff. The diff is then checked before anyone sees it.
    
    
    A first version of this step exists in the prototype but has not been tested against the live API. We will evaluate current Claude models during Milestone 1 and choose based on fix quality and cost.

    Questions
    
    
    
      
    Does PatchPilot work today?
    Only partly. Today it is a concept with a website, an in-browser demo replay and a small command-line prototype that has not been run against the live API. The roadmap above describes how the real engine will be built.
    
      
    Will it merge code automatically?
    No. The plan is to open draft pull requests only. A developer reviews and merges.
    
      
    Are the demo examples real results?
    No. They are hand-written illustrations of the kind of fix PatchPilot aims to produce. No model was called and no tests were run.
    
      
    Which model will it use?
    Claude, through the Anthropic API. We will evaluate current Claude models in the first milestone.
    
      
    Do you have customers or benchmarks?
    Not yet. Early feedback from developers and open-source maintainers is welcome at contact@patchpilot.me.
